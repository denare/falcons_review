This site looks better than most youth-sports sites coming out of Dar es Salaam — clean layout, honest pricing, a working structure. It is still not ready for real marketing traffic. The policies protecting the children's data it collects don't exist yet, the enrollment form can fail silently on a bad connection, and the site is still living on a temporary web address. None of this is hard to fix. All three should be fixed before one more WhatsApp link goes out.

Project Management 5/10 Needs Work

Nobody's decided if this web address is permanent. The site itself is functionally solid, but production readiness assumes basic groundwork — a real domain, a hosting tier that doesn't nap when idle — is locked in. Right now, neither is confirmed anywhere.

Live: the site is still running on the default onrender.com address, no custom domain mapped.

Open this page on the live site
  • Get written sign-off on the production domain and hosting tier before promising a launch date to anyone.
  • Document a rollback plan — a previous working deploy — before pushing the launch build live.
Product 4/10 Needs Work

The pricing is genuinely good work — clear tiers, transparent fees, a fair sibling discount. None of that math actually lives in the system, though. Every discount, installment, and promo gets recalculated by a person, by hand, at signup. That's exactly where refund arguments start.

Live: four overlapping pricing rules (location, siblings, installments, first-month-free) with no checkout enforcing any of them.

Open this page on the live site
  • Freeze the pricing rules — location × siblings × installments × promo — as one written source of truth everyone enrolls against.
  • Confirm the "Join the Roster" newsletter button actually sends its data somewhere, not nowhere.
Business Analysis 3/10 Launch Blocker

The sharpest problem on the whole site. The enrollment form collects a child's name, age, school, and a parent's phone number — and the Privacy, Terms, and Safeguarding policies that should govern all of it are one placeholder page reading "coming soon." For a youth sports business, that isn't a formality to skip.

Live: Privacy, Terms, and Safeguarding all route to the same unfinished stub.

Open this page on the live site
  • Publish a real Privacy Policy and a real Safeguarding Policy before the enrollment form collects one more record.
  • Get documented parental consent before naming a minor by age in a public testimonial ("Baraka M., age 15").
UI / UX Design 6/10 Needs Work

The layout, spacing, and program breakdown are clean and easy to follow — genuinely above average for this space. Two things undercut the trust it's trying to build: every photo on the site is anonymous stock imagery, and the homepage's headline stats currently render as a flat "0+".

Live: "0+ Athletes Trained," "0+ Partner Schools," "0+ Years Running" — visible in the page before any animation runs.

Open this page on the live site
  • Replace stock photography with real academy photos — parents notice the difference immediately.
  • Fix the stat counters so a static "0+" is never what a visitor actually sees.
Frontend Development 6/10 Needs Work

Under the hood this is a modern, well-structured build, and it shows — fast page structure, sensible routing. The catch: hero images are served at full desktop resolution to every device, and the enrollment form only works once JavaScript has fully loaded — a real risk on the connections this audience actually has.

Live: hero images requested at 3840px wide regardless of screen size.

Open this page on the live site
  • Set correct responsive image sizing so phones stop downloading desktop-size images.
  • Add a fallback so the enrollment form doesn't silently fail before the page finishes loading on a slow connection.
Backend Development 5/10 Needs Work

There's no visible evidence of what happens after someone submits the enrollment form — and that absence is itself the finding. That pipeline needs to be confirmed and hardened, especially around a field that will contain a child's personal details.

Live: the enrollment form — its destination and validation are unconfirmed from outside.

Open this page on the live site
  • Confirm exactly where form submissions go, and add server-side validation on every field.
  • Add basic rate limiting so the form can't be flooded with spam submissions.
Mobile Experience 4/10 Needs Work

There's no native app, which is fine — the mobile-web experience is standing in for one. It isn't built for the connectivity this audience actually has, though. A parent who loses signal mid-form loses everything typed, with nothing saved and nothing retried.

Live: the only backup contact channel is a raw WhatsApp link, no SMS or offline fallback.

Open this page on the live site
  • Add offline handling so a dropped connection doesn't wipe a half-finished enrollment form.
  • Add a fallback contact option beyond WhatsApp, for the moments WhatsApp itself isn't reachable.
Quality Assurance 4/10 Needs Work

Four different entry points into the contact form, each pre-filling a different subject line, all need to be checked individually — and there's no sign any of this, or the pricing table's arithmetic, has been tested under real 3G conditions rather than office wifi.

Live: one of four differently-tagged paths into the same form — worth checking each still works.

Open this page on the live site
  • Test every "Enroll" and "Book Trial" link to confirm it pre-fills the right subject line, every time.
  • Run and log a full test pass on a throttled 3G connection before calling anything launch-ready.
Security 3/10 Launch Blocker

A public form with no visible rate limiting is collecting children's personal information, with no published policy governing how it's stored, who can see it, or how long it's kept. That combination is the single biggest risk on this site.

Live: name, age, school, and guardian phone collected here, with the linked Safeguarding policy still a placeholder.

Open this page on the live site
  • Run a basic security scan on the live form and fix any exposed data routes or missing security headers.
  • Lock down who can access submitted enrollment records, and for how long they're retained.
Data Engineering 4/10 Needs Work

The homepage promises to show real numbers — athletes trained, schools partnered, years running — and currently shows none of them. That's a small symptom of a bigger gap: there's no evidence any of the site's lead data lives in one real, structured place.

Live: all four hero stats read "0" in the page before any script runs.

Open this page on the live site
  • Put every lead and enrollment submission into one real database, not a mix of inbox and spreadsheet.
  • Replace the static "0+" stats with real, current numbers — or remove them until they are real.
DevOps 5/10 Needs Work

The site is still living on a temporary Render web address with no confirmed custom domain, and it's unclear whether it's on a tier that stays awake between visits. If it isn't, the first visitor after a quiet spell could wait 30-60 seconds and assume the site is broken.

Live: check the address bar — still falcons-academy-v1.onrender.com, no custom domain.

Open this page on the live site
  • Move to an always-on hosting tier and finalize the custom domain before any real traffic arrives.
  • Set up basic uptime monitoring so a failure gets caught before a parent reports it.
